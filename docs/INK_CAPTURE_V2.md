# Ink capture recipe 2

> Not: Buradaki kanıt kayıtları (arındırılmış ölçümler, ham analiz çıktıları) özel tutulur ve herkese açık depoda yer almaz.

`prepare_ink_append_v2(snapshot, source_stroke_id, *, new_stroke_id, samples, now_ms)` prepares an offline edit. `CloudAPI.append_ink_stroke_v2(..., operation_id)` performs the frozen, conflict-checked transaction. `project_ink` uses the v2 builder for its `appendInk` capability; geometry output remains schema 1. The root application must retain `recipeVersion: 2` in saved jobs and dispatch older jobs to their original v1 API.

Samples use current **document-page coordinates**, pressure 0–1, relative integer milliseconds starting at zero. CSS scaling belongs to the UI coordinate conversion. There are no browser tilt/azimuth conversions in this profile. Source brush and string-table bindings must already exist and validate. Supported templates remain FountainPen and InkPen2, orientation zero, ordinary compressed strokes.

The native reader applies float32(page width / stored owner width) to XY, pen size, fixed width and initial tolerance. A new capture already in page coordinates therefore stores the current page owner extent, and only these three source style values are scaled. Existing binary stroke records remain byte-identical. The six synthetic native-reader cases and source RVAs are recorded under özel kanıt arşivi; these verify channel/style conversion, not native brush pixel fidelity.

For the narrow cache-bearing profile, every media entry must have a validated metadata hash, matching tree entry and either one sole cache reference/refCount 1 or no reference/refCount 0. Unknown backgrounds, PDF/custom content, foreign or shared references fail closed. The affected map is removed and its file metadata refCount becomes 0, with a new internal tick and hash. The file entry, original file hash, upload token and remote bytes are retained. No file deletion or replacement upload is attempted. Native `ClearCanvasCacheData` calls media `Release`; native page merge clears the previous cache map and copies the incoming map; the serializer omits an empty map.

CompareForUpsync must return exactly the affected page, layer, new stroke and released content-file metadata IDs in their correct typed hierarchy. Upload contains the full note tree, required page/layer metadata, the new stroke object, requested file metadata and one new stroke binary. No body, old stroke or media binary replacement is sent. Successful publication still requires full semantic XML and exact opaque-part readback. A missing cache removal, metadata drift or uncertain POST is not silently retried.

The cache and owner conversion are verified offline on the controlled probe and with synthetic tests. The parent subsequently received HTTP 201 and verified complete Cloud readback: two pages retained, two original strokes plus the new stroke, and append capability still available. The sanitized receipt is özel kanıt arşivi. Rendering confirmation on the other device remains pending; server readback alone is not device visual proof.

## Recipe 3: explicit colour and size (2026-10-26)

`prepare_ink_append_v3(..., color_argb, pen_size)` and `CloudAPI.append_ink_stroke_v3` are recipe 2 plus two style values for the new stroke only. Field 2 (ARGB) is set; alpha must be 0xff. Field 3 (pen size) is set in page units (0.5–128). Fixed width (field 8) follows pen size when it equalled it, otherwise it scales by the same factor; initial tolerance (field 13) keeps its ratio. Observed on the controlled 007 strokes: fixed width equals pen size and tolerance is 0.256 × pen size. Pen name, advanced settings and every other brush byte come from the template stroke on the same page. Template values reproduce recipe 2 bytes exactly (tested). A batch is recipe 3 only when a stroke differs from its template; recipe 2 batches are unchanged. One controlled Cloud write on note 007 (red, size 20) passed full readback on 2026-10-26 (özel kanıt arşivi); its device rendering is not yet confirmed.
